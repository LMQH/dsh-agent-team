> **这是本插件唯一的设计真源。** 任何与本文冲突的实现都算缺陷，无论它看起来多合理。
> 每条都标注了**谁决定的**。标注「用户」的条款，代理无权自行更改或"顺手优化"。
>
> 立宪：2026-10-14（用户指出「毫无章法约束，也没有固定化的宪法记忆」之后）
> 违宪记录见文末——写下来是为了不再犯，不是为了检讨。

## 一、定位与共存

### C1 官方优先，本插件让位　【用户决定 2026-10-14】
官方「智能体团队」插件启用时，**用户用官方那张卡片**，本插件**不显示任何东西**；
官方关闭后本插件自动接管它原来的位置。
> 违反记录 V1：代理在做"自有身份卡片"时把这条**静默反转成"两张卡片并存"**，用户未批准。

#### C1.1 实现机制 = 同槽位遮蔽　【用户裁决 2026-10-14，机制"甲"】
不写运行时检测，改用 DSH 内置的遮蔽语义。实测事实（`_tools/probe-slot-shadowing.js`，
真实 `SlotCore`）：

| 事实 | 结果 |
|---|---|
| `conversation.session.header.actions` 是 **list 槽**，`id` 决定「格子」，每个格子只渲染一个胜出者 | 胜出者按 `(priority ?? 0)` 升序取第一个 |
| 同 id + 不同 priority | **不抛错**；2 条记录、1 个胜出者（官方默认 0 胜出）→ 本插件自动让位 |
| 加载顺序反转（先注册本插件） | 官方照样胜出 → 与加载顺序无关 |
| 官方缺席 | 本插件（priority 100）成为唯一胜出者 → 自动接管 |
| 同 id + 同 priority | 抛 `already has an entry with id` ← 第一版整页起不来的真正原因 |

因此本插件的注册是：**同 id（`agent-team`）+ order 相同（-20）+ priority 100**，
并且**整个注册语句外包 try/catch**：官方将来若真用同一个 priority 占位，
register 抛错会被兜成「让位」，而不是让异常冒出去
（客户端 entry 抛错 → 启动激活审计在 mount 之前 throw → 整个 GUI 停在
"Failed to load plugins"，第一版实测过）。

### C2 让位不需要用户操心　【用户决定 2026-10-14："只要自动检测"】
让位由 priority 遮蔽自动生效，用户**不需要**每次去插件管理页手动关本插件。
手动停用仍然可用作兜底，但**不是**让位的前提条件。
> 违反记录：无。

### C3 身份坐标：会撞车的必须自有，不撞的可以有间相同　【用户决定（含 2026-10-14 修订）】

| 坐标 | 本插件 | 官方 | 为什么 |
|---|---|---|---|
| slot id | `agent-team`（**与官方相同，有意为之**） | `agent-team` | C1.1 的遮蔽要求同一个「格子」 |
| order | `-20`（同官方） | `-20` | 官方缺席时正好补上它原来的位置 |
| **priority** | **100** | 默认 `0` | 决定谁胜出；数值大者让位 |
| locale ns | `dsh-team-workflow` | `agent-team` | **同值会抛错**（`locale namespace ... already has locale`） |
| CSS 前缀 | `_twf_` | 官方自带哈希前缀 | 同值会污染官方样式 |
| 模块 id | `@local/dsh-team-workflow` | 官方包名 | 不得冒充官方 |

**要点**：C3 的目的从来不是"坐标必须全部不同"，而是"不许撞到会抛错的那些"。
第一版（V0）照搬官方 bundle 时，撞的是 locale ns 与同 priority 的 slot id。
> 违反记录 V0：第一版沿用官方坐标 → 与官方同时启用时整个页面起不来。

### C4 注册与显示是两件事
本插件**始终注册**（坐标安全，见 C1.1/C3）；"官方在场时不显示"由遮蔽机制达成，
**不得**用"干脆不注册"或"检测到官方就不 apply"来实现——那会引入加载顺序依赖。

## 二、卡片行为（对齐官方，不得自创）

### C5 外观照搬官方　【用户决定 2026-10-14：「卡片，GUI 样式」「改回来」】
紧凑角色卡观感、面板尺寸、两列网格、状态点、小字排版，以及 portal 定位
（`useAnchoredPosition`）、悬停展开、外部点击关闭、Esc 关闭、aria 属性，
**全部照搬官方**。允许的改动只有内容文案与身份前缀。
> 违反记录 V2：代理自研了"每行三段文字的大卡片"，用户反馈「怎么改得面目全非的」。

#### C5.1 角色行的内容口径 = 五项　【用户决定 2026-10-14（第二次 UI 裁决）】
角色行**只显示**：状态点 + 角色中文名 + Tag（角色 id）+ 状态词 + 职责简述，**即可**。
`产物 / 边界 / 能力` 三行与行内悬空警句**从卡片移除**（迁到 C20 的插件管理详情区块）。
行悬停提示**固定为官方那句「打开成员会话」**，不再拼接技能信息。
行仍然复用官方 `.member / .memberDot / .memberText / .memberName / .currentTag / .meta`
类名与官方状态口径（C6）、点击语义（C7）不变。
> 理由（用户原话）："每行内容，应当借鉴官方的显示设计"。上一版把三行内容塞进卡片，
> 观感偏离官方；本次收敛回官方那种"一行状态 + 一行小字"的密度。

### C6 必须是真实运行状态　【用户决定 2026-10-13 实测反馈】
状态口径与官方一致：本地镜像 `useSessionStatus` 优先 → host 快照 `useSessions.byId`
兜底 → 用 `??` 而非 `||`；相位非 `active` 时直接显示相位。不得用静态值冒充状态。

### C7 点击成员行进入该成员的会话详情　【用户决定 2026-10-14】
实现照抄官方（**不许自创**）：
```js
ctx.uiWorkspace.openSession({ parentSessionId, childSessionId, mode: "continuable" })
```
本插件的角色行通过官方同一个入口调用它：`openTeammate(sessionId, liveId)`。

**例外（可以禁用）**：该角色**尚未派发**（没有成员会话可打开）、
或官方也视为不可点的 `failed` / `provisioning`。
> 违反记录 V3：代理曾把所有成员行设成 `disabled: true` 并删掉 onClick。

### C8 详情要能看到四类"是否启用"信息　【用户决定 2026-10-14，四项全要】

| # | 内容 | 呈现位置 |
|---|---|---|
| a | 成员会话是否在运行（运行中 / 未运行 / 准备中 / 失败） | 行内状态词 |
| b | 该角色是否已被派发（有/无对应成员） | 行内状态词 `未派发` |
| c | 技能可加载性，含悬空技能 | **迁到插件管理详情区块**（C20.2）；行内与悬停都不再出现 |
| d | 本插件自身的启用/停用状态 | 面板顶部**状态卡片**（含「打开插件管理」按钮，见 C20.3） |

### C9 本插件的 UI 不得冒充官方
触发器文案为「Agent 团队工作流」/「Agent Team Workflow」，不得使用官方文案。

## 三、内容与数据

### C10 角色表唯一来源是资源包　【用户决定】
10 个角色来自 `roles.json`（由 `_tools/sync-roles-from-pack.js` 从
`sources/omp/agents/*.md` 生成）。**不得在别处另写一份角色表。** 按需实例化，不常驻。

### C11 成员名 = 角色 id　【代理推断 2026-10-14，待用户确认】
派发时 `spawn_teammate` 的 `name` 必须等于角色 id。依据：策略层 `dispatchInfo` 用
`input.name` 作为授权匹配的 role，且是**精确匹配**（不通配）；卡片按「角色 id + `-` 前缀」
容错，两边口径不一致会出现"卡片显示状态、策略层认为未授权"。

## 四、工程约束

### C12 产物只能由生成器生成
`dsh-team-plugin/client.js` 只能由 `_tools/build-client.js` 生成，**禁止手改**。
生成器以官方 bundle 为外壳打精确锚点补丁；任一锚点不命中即报错退出。

### C13 落盘前硬断言
- 官方 CSS 前缀（`_2tNPVa_`）与官方包名：**0 处**
- 官方 slot id：**恰好 1 处**，且只能出现在 `const OFFICIAL_SLOT_ID = "agent-team";`
  这个只读常量里（2026-10-14 修订：遮蔽机制必须能点名官方，但只允许点名一次）
- 自有坐标（locale ns / CSS 前缀 / 模块 id）齐全；`priority` 与 `try/catch` 在位

### C14 验收门 6a–6h 必须全绿，且门本身要有反证
`_tools/verify-acceptance.js` 是回归门。**任何门的改动都必须先把它弄红一次**，
确认它真的会红，否则视为无效门。当前 25/25。

### C14.1 规则层的真源是 `instructions/AGENTS.md`，不是 `~/.dsh/AGENTS.md`
`install.sh` 会拿 `instructions/AGENTS.md` **覆盖** `~/.dsh/AGENTS.md`（覆盖前备份到
`~/.dsh/team/.install-backups/`）。所以：

- 手改 `~/.dsh/AGENTS.md` 的规则**下次安装就没了**（2026-10-14 实际发生过一次：
  「派发团队角色一律用 `spawn_teammate`」这条用户决定被静默丢失，门 7a 立刻变红抓到了它）。
- 规则要改就改 `dsh-team-workflow/instructions/AGENTS.md`（源），然后重跑 `install.sh`。
- 门 7a/7b 盯的就是"这条规则还在不在"。

### C15 客户端改动需要重启 DSH
`client.js` 在进程生命周期内被缓存，**刷新页面不够**，必须重启 DSH 应用。

### C16 代理不得自授权　【用户决定（策略层强制）】
破坏性操作、派发授权一律需要用户明确授权。授权记录的 `issued_by` 必须来自人类；
空 `issued_by` 的记录结构性无效。代理不为自己写签发记录。

## 五、变更规则

### C17 改宪法才能改代码
要改上述任何一条：**先提出改动内容 + 理由 + 影响面 → 用户确认 → 改宪法 → 改代码 →
同步更新验收门与证据**。不允许"先改了再说"。

### C18 不得静默反转
发现已确认的决定有更优做法时，**必须先提出来让用户决定**，不得在实现里顺手改掉。
> 这条正是 V1 的教训。

### C19 改了就要有证据
每次实质性改动都要在 `evidence/` 留下：改了什么、为什么、怎么验证的、反证是什么、

## 五之补：插件管理页与入口（C20）

### C20 插件管理页不杂糅，入口走官方公开契约　【用户决定 2026-10-14（第二次 UI 裁决）】

#### C20.1 locale `meta` 只留一句话
插件管理卡片上的标题与描述只写"这是什么"，**不得**再把 10 个角色、职责、产物、能力边界、
零依赖/无门控之类的结构化内容塞进 `description`——那就是用户说的"全杂糅到一起"。

#### C20.2 结构化内容挂 `plugins.detail.section`
10 角色的职责 / 产物 / 边界 / 能力（只读可写）以及悬空技能告警，全部移到本组合包在
插件管理页的详情区块，注册坐标：`name: "plugins.detail.section"`、`id: "team-workflow-roles"`、
`locale: <自有 ns>`。该槽位由官方 `dsh-client-ui-plugin-manager` 页面声明
（`kind: list, scope: root`），条目按页面传入的 `subject` 渲染——**只对
`subject.kind === "bundle" && subject.pkg.name === 本插件模块 id` 返回区块，其他 subject 一律返回 `null`**
（对别人的页面无话可说，也不许越界）。C8(c) 的信息因此仍然可查，只是换了落点。

#### C20.3 面板状态卡片上的按钮 —— 打开**本插件自有配置弹窗**
顶部那条"本插件接管中"必须做成**卡片**（图标 + 文案 + 圆角/底色/描边），不是一行纯文字；
卡片右侧按钮点击后打开**本插件自己的配置弹窗**（形态与配置口径见 C21），**不再跳官方页面**。

> 【用户决定 2026-10-14（第三次 UI 裁决）】原 C20.3 要求按钮调 `pluginNavigation.openBundle`。
> 实测点下去落在**官方插件管理页**——那是官方的侧栏面板，不是配置"我这个插件"的地方。
> 用户原话：「我要的是可配置我自己插件的弹窗或界面或侧拉」。

官方入口**不删**，降级为弹窗内的次级链接「在插件管理页中查看」：点击仍调
`ctx.pluginNavigation.openBundle("<本插件模块 id>")`；服务缺席（官方管理器未挂载）时降级为
`ctx.layout.selectPanel("plugins")`；两者都没有时静默无操作。
服务仍用 `ctx.reflect.get` **懒取**，不写进 `inject`——否则官方管理器缺席时本插件连激活都做不到。
**诚实边界**：平台**没有**"插件管理弹窗"API，`openBundle` 打开的是**侧栏「插件」面板**并直达该组合包详情页。

#### C20.4 共享任务板借鉴官方设计
`workflowRoster()` 必须把 `agentTeam` 投影里的 `tasks` 与 `failure` **原样透传**，
让官方那套任务卡（两行截断展开、Owner/依赖/写入范围/重叠告警、数量徽标）与失败横幅真的渲染出来；
空态用官方原文，不再替换成工件链说明（工件链说明改挂 C20.2 的详情区块 `detailNote`）。

## 五之补之二：自有配置界面（C21）　【用户决定 2026-10-14（第三次 UI 裁决）】

用户原话：「打开插件管理，怎么跳转到是 DeepSeekHarness 官方页面，我要的是可配置我自己插件的弹窗或界面或侧拉」
→ 用户选定：**模态弹窗**形态；**行为层与展示层都做**；**授权引入 `@deepseek-ai/schemastery`**；
安装方式**只保留官方 pnpm 通路**（废弃符号链接）。

### C21.1 形态：用官方 `Modal`，不自己造浮层
配置界面做成**模态弹窗**，用 `@deepseek-ai/dsh-client-ui-primitives` 的 `Modal`
（`open` / `onClose` / `title` / `closeLabel` / `children` / `footer`）。
**不得**自建遮罩、Esc 处理、Tab 走位或焦点归还——那是官方的可访问性契约，`useModalLayer` 已负责
（顶层 Esc、Tab 循环、关闭后焦点归还、`isBehindModal`）。表单外观用同包的 `SettingsForm` +
`SettingsValueField` + `Switch`，不另起一套视觉。

### C21.2 配置口径：6 项，**默认值一律等于当前行为**

| 字段 | 类型 | 默认 | 消费点 |
|---|---|---|---|
| `disabledRoles` | string[] | `[]` | 宿主 `/team` 名册与简报排除；卡片里这些行显示为已停用 |
| `autoloadSkills` | boolean | `true` | 宿主角色简报的"自动加载技能"段与派发 prompt |
| `routeGuard` | boolean | `true` | 宿主 `/team route` 是否强制写明触发原因 |
| `showTaskBoard` | boolean | `true` | 卡片是否渲染共享任务板 |
| `hideUnassignedRoles` | boolean | `false` | 卡片是否隐藏"未派发"角色行 |
| `forceCompactPanel` | boolean | `false` | 在官方自动紧凑逻辑之上强制紧凑面板 |

**默认值 = 现状**是硬要求：配置功能本身不得改变任何现有行为（默认值下 6f/6h 必须与改前等价）。
六个字段之外**不得**再开口子：五项行（C5.1）、悬空技能必须显式报告（C3）、遮蔽方向（C1）
都是规范定死的，不因配置而改变。

### C21.3 单一真源：宿主 volatile Config
配置**只有一份**：宿主半用 `@deepseek-ai/schemastery` 声明 `Config`，六个字段全部 `.volatile()`；
持久化走当前 profile 的 Cordis patch（官方设置服务）。客户端经 `ctx.configForms.get("team-workflow")`
读写，**不得**另存 localStorage、**不得**自建配置文件。
本包在 profile 里的**条目 id 固定为 `team-workflow`**——客户端按这个 id 寻址，改名即断。
官方插件管理页的自动生成表单用
`ctx.inject(["settings"], (child) => child.effect(() => child.settings.configure({ auto: false }, ctx.fiber)))`
**关掉**，避免两个入口写同一份配置。
**降级纪律**：`ctx.configForms` 缺席或读写被拒时，弹窗显示"当前不可写"，**绝不让异常冒出去**
（同 C1 的让位纪律——客户端 entry 抛错会让整个 GUI 停在 "Failed to load plugins"）。

### C21.4 依赖与安装：只保留官方安装
- `dependencies`: `{"@deepseek-ai/schemastery": "3.18.4"}`（与 app 内置版本一致）。
- `dsh.client.inject` 增补 `@deepseek-ai/dsh-client-ui-settings`（提供 `configForms` 服务）与
  `@deepseek-ai/dsh-client-ui-layout`；客户端运行期 `inject` 增补 `"configForms"`。
- 安装**只走官方 pnpm 通路**（写 profile 的 `dependencies` 与 `dsh.profile.bundles`）。
  **代价必须写进文档**：装完之后改工作区**不再自动生效**，每次改动要重新生成 → 重新安装 → 重启（C15）。
