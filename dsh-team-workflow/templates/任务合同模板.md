# 任务合同模板（DSH 版）

> 迁移辅助模板，**不是**已生效团队标准。来源：资源包 `templates/任务合同模板.md`
> 与 `sources/omp/skills/team-workflow/SKILL.md` 的 Task contract 一节。

## YAML 合同（嵌入 `team_task_create` 的 `description`）

```yaml
task_id: <唯一稳定标识；建议回填看板 task-<n>>
repository: <目标仓库绝对路径>
worktree_or_revision: <分支 | commit SHA | "uncommitted+<内容哈希>">
owner_role: <角色 id，见 ~/.dsh/roles/>
allowed_paths:                # 额外授予的写入路径（工作区外的路径只能靠它授权）
  - <绝对路径或相对仓库根的路径前缀>
denied_paths:                 # 显式排除的路径；**路径隔离必须靠它**
  - <例如 QA 合同必须排除被测实现目录>
input_artifacts:              # 含路径与 owner
  - path: <...>
    owner_role: <...>
output_artifacts:
  - path: <...>
    owner_role: <...>
dependencies: [<必须先完成的 task_id>]
acceptance_criteria:          # 可观察、可验证；必须含拒绝/边界路径
  - <主流程：输入 → 期望可观察结果>
  - <拒绝路径：非法输入 → 期望被拒绝且不留副作用>
  - <回归范围：...>
reviewer_role: <与 owner_role 不同的角色 id>
required_gates: [qa, code-review, compliance]   # 按分诊结果取所需
authorization_record: <动作 + 确切目标 + 用户消息引用 + 时间 | "未授权">
```

## 填写要点

- **目标/非目标**：写可观察结果与明确排除项。Fast 自行执行的小事不要求形式化合同。
- **契约/所有权**：列出共享 API/schema、文件 owner、唯一集成者与兼容迁移步骤。
  多个 writer 触及同一文件而无唯一集成者时**拒绝派发**。
- **允许路径**：写路径前缀，不写"相关文件"。
- **路径隔离必须用 `denied_paths`，不能只靠 `allowed_paths`**（本机实测结论）：
  `allowed_paths` 只**增加**工作区外的可写路径；在工作区**内部**它不做白名单收窄。
  因此"QA 不得修改被测实现"必须显式写成 `denied_paths: [<被测实现目录>]`，
  否则 QA 写 `src/` 仍会被放行（实测 `policy_check.js` 在只有 `allowed_paths` 时 exit 0）。
  正确写法：
  ```yaml
  # qa 合同
  allowed_paths: [<repo>/tests, <repo>/delivery]
  denied_paths:  [<repo>/src]
  ```
  派发时该合同必须成为**活动任务合同**（`~/.dsh/team/task-contract.json`），
  否则钩子读不到 `denied_paths`。
- **验收**：主流程 + 拒绝/边界路径 + 回归范围 + 实际证据要求。
  纯文档任务验收"交付物可核查"，不要求测试运行。
- **独立 reviewer**：实现类角色（`backend`/`frontend`/`harness`）不得以另一实现类角色作为唯一 reviewer。
- **授权**：`authorization_record` 为"未授权"时，合同不得包含需要授权的动作。

## 汇报格式（成员返回时必须包含）

```yaml
status: complete | blocked | needs-authorization | needs-decision
revision: <commit SHA | uncommitted+<hash> | N/A>
commands_run:            # 逐条原样，含 exit_code
  - command: <...>
    exit_code: <n>
changed_paths: [<...>]
evidence: [<证据文件路径>]
risks: [<...>]
uncovered: [<...>]
next_owner: <角色 id>
next_gate: <qa | code-review | compliance | product-acceptance | none>
```

## DSH 硬事实（每次派发都应告知成员）

- 共享同一工作目录与文件系统，编辑立即可见；无 worktree、无文件锁。
- `write_scopes` 仅**咨询性**：只在路径重叠时告警，不阻止也不授权写入。
- 任务所有权不会因空闲/中断/失败自动释放。
- 任务更新是 compare-and-set，必须使用最新 `revision`。
- 提交、部署、密钥操作与破坏性清理由用户另行明确授权。
