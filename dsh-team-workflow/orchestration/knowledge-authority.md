## 仍然生效的权威规则

即使没有知识库，以下规则照常成立：

1. **权威顺序**：当前用户指令与明确授权 → 仓库宪法/`AGENTS.md`/已生效 ADR/保护规则 →
   已批准团队规范与 ADR → 任务与获批工件 → 记忆与历史摘要。
2. **草案不得冒充批准**。`scope: team-draft`、未批准 ADR、历史记忆、未验证报告
   一律标注为草案，不得当作约束使用。
3. **`raw/`（若将来接入）不可改写**；团队标准/ADR 只有用户批准后生效；成员只读，
   主 Agent 管理索引与状态。
4. **与代码版本相关的工件留在目标仓库**（`<repo>/delivery/`），知识库只做索引。
5. 个人 vault 内容默认私有，不得为项目工作批量读取或改写。

## 若将来接入知识库

必须先取得以下信息，再启用只读成员与主 Agent 管理：

- vault 的绝对路径与存在性证据；
- 读写权限边界（谁可写、写哪些子目录、`raw/` 是否只读）；
- 索引与状态文件的归属与格式；
- 团队标准/ADR 的批准流程与 `approved` 标记约定；
- 版本绑定策略（仓库工件 ↔ vault 索引的双向引用）。

在取得这些之前，任何"知识库已接入"的声明都是未复刻。

## 冲突处理

出现冲突时按权威顺序选用，并**保留冲突记录**：

```yaml
conflict:
  between: [<来源 A 路径>, <来源 B 路径>]
  chosen: <来源>
  reason: <权威层级或用户明确指令>
  unresolved: <true | false>
  needs_user_decision: <true | false>
```

冲突未决时返回 `needs-decision`，不得由 Agent 单方面裁定生效规范。
