# DeepSeekHarness 团队安全与操作边界（RULES）

> 来源：OMP `~/.omp/agent/RULES.md`（快照见资源包 `sources/omp/RULES.md`）的语义移植。
> 路径、工具名与强制机制已按 DeepSeekHarness 实际能力重写。本文件是**边界声明**；
> 工具层强制由 `~/.dsh/team/hooks.json` 的 PreToolUse 钩子承担，OS 层由 DSH 文件沙箱承担。

## 硬边界

- **未经用户对确切动作的明确授权**，不得提交（commit）、推送（push）、部署、操作真实基础设施或访问账号/密钥。
- 不得通过 Agent 任务修改 `.env` 文件、CI/CD 配置、受保护部署配置，或知识库 `raw/` 源文件。
- 不得把草案、记忆或未验证报告呈现为已批准的需求、ADR、规范、测试结果或授权。
- 实施 owner 不得审查自己的 diff；独立 QA、代码审查与合规结论必须指明被审 revision。

## 授权状态与记账

- 每次派发前按 `agent-usage-ledger` 向 `~/.dsh/team/ledger/agent-ledger.jsonl` 追加派发记录。
- 授权记录写在任务合同的 `authorization_record` 字段，须指明：动作、确切目标、用户原话或消息引用、时间。
  DSH 钩子在派发与破坏性命令上读取该记录；**缺失或不匹配即阻断**。
- 授权是**逐项**的，不是逐类的：授权"部署 staging"不等于授权部署 production；
  授权发布不等于授权清理；授权构建候选镜像不等于授权晋级。

## 跨项目操作安全（构建 / 候选 / 发布 / 清理）

- 把**构建、候选验证、发布、清理视为四个独立阶段**。构建成功或候选健康**不**授权晋级、部署或清理；
  每道门单独报告结果与证据。
- 每次容器镜像构建后、在任何其他操作或下一次镜像构建之前，必须清点（**不可截断**）：
  完整镜像 ID、完整容器 ID、每个容器的镜像引用与解析后镜像 ID、所有具名与匿名卷、
  每个容器的卷挂载，均限定在受影响的 Docker context 内。
  记录构建输出的确切工件身份与既有的发布/回滚工件。
  **清点不可得即停止，并把该门报为未通过。** 仅凭 tag、短 ID 或 `latest` 不构成不可变证据。
- 发布或清理前，必须确认上一已知良好工件及其配置/数据兼容性仍可用于回滚。
  若更早的回滚工件缺失或不可访问，明确把回滚/发布门报为**未通过**；
  不得因为候选健康就宣称成功，也不得重建一个"据称等价"的镜像并称之为同一工件。
- 启动测试容器前，检查生效镜像**继承的 `VOLUME` 声明（含来自基础镜像的声明）**，
  并显式说明它们会创建的匿名卷。
- 测试结束后，按**实际 Compose project** 清点资源：测试容器、具名与匿名卷及其挂载、被取代的镜像。
  优先只保留运行时必需工件与已验证的回滚工件；
  **不得**从 `stopped`、`anonymous`、`reclaimable` 推断删除安全性。
  测试完成**不是**清理授权；对每一项拟删除资源，都要走下面的"清单确认—删除前复核—删除后核对"。
- 清理是独立的破坏性操作，**永不**由构建、验证或发布批准隐含授权。删除任何 Docker 资源或数据库之前：
  1. 提交最终逐项清单：资源类型、完整 ID/名称、适用时的镜像引用、context/host、回滚与数据影响；
  2. 取得用户**对该确切清单的单独明确确认**；
  3. 删除前立即重新清点；身份或范围变化即**作废**上述确认；
  4. 只删除清单内条目；
  5. 删除后重新清点，确认清单外资源（含回滚工件）仍在；
  6. 有任何偏差即报告并停止。
- 禁止用 `prune`、通配符或整体 Compose 移除替代逐项枚举；禁止清空主机废纸篓，除非用户明确授权该确切范围。

## 受保护路径（工具层阻断，见 `~/.dsh/team/hooks.json`）

- `.env`、`.env.*`、`*.pem`、`*.key`、`id_rsa*`、`~/.ssh`、`~/.aws`、`~/.dsh/.credentials.yaml`
- `.github/workflows/**`、`Dockerfile`、`docker-compose*.yml`、`**/deploy/**`、`k8s/**`
- 任何知识库 `raw/` 目录
- 会话工作目录之外、且当前任务合同未授权的路径

## 残余风险（不得声称已覆盖）

- DSH 钩子以工具名为匹配主体，**只覆盖经由受匹配工具的动作**；
  间接写盘（构建脚本、生成的产物、格式化器）可能绕过。
- 钩子在崩溃或非 2 退出码时**失败开放**（工具继续执行）。
- 文件沙箱模式（`read-only`/`workspace-write`/`danger-full-access`）是第二层，
  受会话模式影响；`danger-full-access` 下不再提供路径约束，此时仅钩子与人工审阅有效。
- OMP 原插件用正则识别枚举命令，**不是**通用 OS 路径沙箱；本复刻同样不宣称全面隔离。
