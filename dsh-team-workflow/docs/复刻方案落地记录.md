# 复刻方案落地记录（02-复刻方案 → DSH 实现）

来源：资源包 `02-DeepSeekHarness复刻方案.md` 的七层迁移顺序。
本文件记录每层在**本机实际 DSH** 上如何落地、依据了哪些经核实的平台事实、以及哪些假设被实测推翻。

## 平台事实（通过读取随应用分发的 `app.asar` 内 `@deepseek-ai/*` 包确证，非猜测）

| 事实 | 来源包 | 对复刻的影响 |
|---|---|---|
| 用户级指令文件是 `$DSH_HOME/AGENTS.md`（默认 `~/.dsh/AGENTS.md`），项目级为项目根到 cwd 的 `AGENTS.md`/`CLAUDE.md` 链 | `dsh-agent-instructions` | 宿主规则层落在这里 |
| **不解析 `@path` 导入**，候选文件名固定，无 `@~/.codex/...` 语法 | 同上 | OMP 的 `@~/.codex/AGENTS.md` 必须**内联展开** |
| 技能根（rank）：`<project>/.dsh/skills`(100)、`<project>/.agents/skills`(200)、`customSkillDirs`(300)、`~/.dsh/skills`(400)、`~/.agents/skills`(500) | `dsh-skill-filesystem` | 技能安装在 `~/.dsh/skills`（全局）|
| 技能**只发现一层**：`<root>/<name>/SKILL.md` 或 `<root>/<name>.md`；嵌套 `**/SKILL.md` **不会**被发现 | 同上 | 多文件技能必须放进一个 bundle 目录；用校验器兜住 |
| frontmatter 非法（缺 `description`、name 非 kebab-case、布尔拼写错）会被**静默跳过**，只在宿主日志告警 | 同上 | 必须有独立校验器，不能靠"平台会报错" |
| 没有角色自动加载、没有 `agents/` 注册表、没有 `skill://` URI | 全平台 | 角色必须变成**派发提示词合同** |
| Agent Team 工具：`spawn_teammate`/`send_message`/`list_agents`/`wait_agent`/`interrupt_agent`/`team_task_*` | `dsh-experimental-agent-team`、`dsh-experimental-tool-agent-team` | 任务合同与共享任务板的落地机制 |
| `write_scopes` 是**咨询性**，仅在 in-progress 任务路径重叠时告警，不阻止 claim、不授权写入 | 同上组件 README | 不得声称其为写保护 |
| 成员共享同一 cwd 与文件系统；无 worktree、无文件锁；无自动所有权释放 | 同上 | 并行只能靠路径隔离 + 人工审阅 |
| PreToolUse 命令钩子：`dsh-hooks-claude-code` 桥接到 `tools/pre-execute` 瀑布；matcher 是**工具名**，claude-code 方言下 `"a|b"` 为字面量或 | `dsh-hooks-claude-code` | 策略层落地机制 |
| 钩子 stdin 为 `{session_id, transcript_path, cwd, hook_event_name, tool_name, tool_input}`；exit 2 = 阻断并把 stderr 作为理由；**其它非零退出码与崩溃都是非阻断失败** | `dsh-hook-protocol` | 策略程序必须永不崩溃（fail-closed） |
| `updatedInput` 解析但不生效；`allow` 不预批准；`ask` 仅在 claude-code JSON 输出下可用 | 同上 | 只依赖 `deny`（exit 2）语义 |
| 钩子配置**进程启动时只读一次** | 同上 | 挂载后需重启才生效 |
| 文件沙箱模式 `read-only`/`workspace-write`/`danger-full-access` 是第二层 | `dsh-sandbox-policy` | 与钩子构成双层防护；`danger-full-access` 下只剩钩子 |
| `desktop` profile 不允许 CLI 启动；可用 `--from-default-profile {acp,headless,sdk,sdk-minimal,web}` 造一次性 profile 做组合校验 | CLI `dsh` | 端到端钩子验证路径 |

## 七层落地

### 1. 宿主规则层
- `sources/omp/AGENTS.md` + `sources/imported/AGENTS.md` 合并 → `instructions/AGENTS.md` → `~/.dsh/AGENTS.md`。
- `@~/.codex/AGENTS.md` 引用**内联展开**（DSH 不支持导入语法）。
- `RULES.md` → `instructions/RULES.md` → `~/.dsh/team/RULES.md`；AGENTS 中显式引用该路径。
- 硬编码的 `/Users/lmqhx/...`、`~/.omp/...` 全部重映射或标为"未配置"。
- 唯一主入口设置"每任务先加载 `team-workflow` 并先选 Fast/Standard/Deep"，见 AGENTS 第 1 节。
- **不覆盖**项目自身更高优先级的已生效规则：AGENTS 第 1 节把项目宪法排在团队规范之上。

### 2. 技能层
- 15 个团队技能 + 9 个共享技能 = 24 → `skills/<name>/SKILL.md` → `~/.dsh/skills/`。
- 资源子目录（`references/`、`scripts/`、`tests/`）随 bundle 迁移。
- 两个不存在的技能（`react-page-implementation`、`branch-diff-static-review`）**不创建空壳**，
  绑定解除并记录在 `skills/MISSING-SKILLS.md`。
- `technical-design-delivery` 保持为**技能**，不提升为独立角色。

### 3. 角色层
- 10 份 `agents/*.md` → `roles/<role>.md`（DSH 派发合同格式：权限、工具、技能、独立 reviewer、门、汇报格式）。
- `model: "@team_*"` 别名**不**迁移、不推断提供商、不复制凭据。
- `autoloadSkills` 语义改为"派发提示词必须显式加载这些技能"，由 `roles/_tools/validate_roles.js` 保证无悬空。
- 5 个无本地定义的角色记为 `dsh-builtin-substitute`，明确"未导入专属定义"。

### 4. 编排/工件层
- `orchestration/triage.md`（三档门）、`dispatch.md`（合同→看板→记账→派发）、
  `artifact-chain.md`（PRD→ADR→Tech Spec→Implementation Plan→Test Spec→QA Report + 登记表 + 失效规则）、
  `gates.md`（独立性与门）、`knowledge-authority.md`（权威顺序与知识库状态）。
- 工件默认落在 `<目标仓库>/delivery/`；`templates/` 提供合同与工件模板。
- 门控键为 revision（commit SHA 或 `uncommitted+内容哈希`），变更即失效重验。

### 5. 策略执行层
- `sources/omp/extension/index.ts` 仅作**语义参考**；`@oh-my-pi/pi-coding-agent` 不引入。
- 重写为 PreToolUse 命令钩子：`policies/hooks.json` + `policies/policy_check.js`
  （路径归一化、`~`/相对/`..` 解析、符号链接 realpath、受保护路径、越界、破坏性命令、派发授权、台账前置写入）。
- 崩溃即失败的语义被显式规避：任何异常路径都返回 `exit 2`（fail-closed）。
- 双层防护：钩子（工具层）+ DSH 文件沙箱（OS 层，模式可切）。
- 原插件的盲区（间接 shell 副作用、未列举命令、符号链接、CI 文件、无授权校验）
  在 `policies/GAP-ANALYSIS.md` 逐条列出覆盖情况。

### 6. 记账与知识层
- 派发前 append-only JSONL：`~/.dsh/team/ledger/agent-ledger.jsonl`（`policies/ledger.js`）。
- **不迁移**旧台账、不伪造历史；被阻断的派发不推进台账。
- 知识库未配置：保留"批准规范高于草案/记忆""版本绑定工件留仓库"的权威规则，
  vault 相关技能显式标注 `KNOWLEDGE VAULT: 未配置`。

### 7. 实际验收层
- `docs/验收执行说明.md` 把 10 项检查翻译为 DSH 可执行步骤与证据要求；
- 实际执行结果与逐项判定记录在 `verification/acceptance-run.md`；
- 明确区分"已复刻/未执行/未复刻"，不用提示词替代证据。

## 被实测推翻的假设

| 假设 | 实测结果 | 处置 |
|---|---|---|
| `@~/.codex/AGENTS.md` 这类导入在 DSH 可用 | 不支持 | 内联展开 |
| 技能可以多文件放在任意嵌套目录 | 只发现一层 | bundle 化 + 校验器 |
| 任务板 `write_scopes` 能防止并发写同一文件 | 仅告警 | 文档与角色合同写明为咨询性，靠路径隔离 |
| 钩子配置可热加载 | 启动时读一次 | 安装器提示重启；提供一次性 CLI profile 校验路径 |
| `desktop` profile 可用 CLI 起进程做端到端钩子验证 | 被应用独占 | 改用 `--from-default-profile headless` + `--dump-config` 做组合校验 |
