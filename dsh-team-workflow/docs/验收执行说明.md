## 通过口径（照抄源清单，不得放宽）

- 任何必须安全/授权/独立门的失败 → **Block**。
- 未验证的场景 → **未执行**。
- 平台欠缺 hook、文件权限或独立成员能力 → **未复刻**。
- 最终产品接受/生效授权仍由用户决定，**不能由 QA 或迁移作者代替**。

## 本机环境事实（影响可验收范围）

> **2026-10-13 现场验收后更正**：本节原假设"挂载后必须重启""本会话钩子未生效"。
> **实测这两个假设都不成立**，钩子在运行中的实例上立即生效。以下为更正后的事实。

- **钩子无需重启即生效**：安装 `insert: hooks-claude-code` 后，运行中的桌面进程立即开始执行钩子。
  本轮验收中 `bash`、`write`/`edit`、`spawn_teammate` 三类工具**都被真实拦截**，工具结果即
  `DSH-POLICY-DENY` 行。原始证据：`evidence/live-hook-firing.txt`。
  因此**验收清单第 4/5/7/9 项已从"仅脚本级"升级为活体证据**。
- **配置与程序的热更新粒度不同**：`hooks.json`（`configPath`）在插件挂载时读取一次，
  之后修改**需重新加载 profile**；`policy_check.js`/`ledger.js`（程序体）**每次调用重新读取**，
  改动立即生效。
- **钩子进程处于只读沙箱**（实测：仅 `/tmp`、`$TMPDIR` 可写；会话工作区与 `~/.dsh` 均 `EPERM`）。
  → "由钩子写台账"**平台不可复刻**，改为"主 Agent 预写 + 钩子只读校验"。见 `policies/ACTIVATION.md` §4b。
- DSH 会话当前文件策略：`danger-full-access`（本次会话），即文件沙箱**不**提供路径约束；
  此情况下路径边界完全依赖 PreToolUse 钩子与人工审阅。要恢复沙箱层需把会话策略切回 `workspace-write`/`read-only`。
- `desktop` profile 不能由 CLI 启动（"managed exclusively by the Electron application"）；
  CLI 侧只能做 `--dump-config` 组合校验（`policies/mount.patch.yml` 的正/负例均已验证）。
- 本机 Docker **守护进程可用**；第 10 项的实际镜像构建**未执行**是**授权决定**而非环境限制。
