勘察对象：DeepSeek Harness `0.2.0-rc.2`（Electron 打包，`asar` 内源码）。
勘察方式：**全程只读**——只用仓库内已有的只读检视器 `_tools/inspect-dsh-checkout.js` 读取 `app.asar`，加上对 `~/.dsh/profiles/desktop/` 的只读读取与 `ls`/`command -v` 查询。
本文件是本轮勘察**唯一写入的文件**。

结论速览（每项判定见对应章节）：

| 问题 | 判定 |
|---|---|
| Q1 插件包最小结构与注册 API | 已查清（有官方随包文档 + 4 个可读参照实现） |
| Q2a 插件进程内写台账（`<workspace>` / `~/.dsh`） | **能**（证据充分） |

### 0.3 可读性说明（诚实披露）

* `lib/index.js` 是**打包但基本未压缩**（有 `//#region` 段落注释、JSDoc、`# sourceMappingURL`）。`dsh-tools/lib/index.js`（158 KB）、`dsh-plugin-manager/lib/index.js`（86 KB）、`dsh-subagent/lib/index.js`（135 KB）、`dsh-experimental-agent-team/lib/index.js`（73 KB）我都能读。

* `lib/client.js` 是浏览器 bundle（`window.__ModuleLoader__.load({id, factory})`），**可读**（非压缩），只是内联了 CSS 字符串。

## 1. 参照实现：内置实验 Agent 团队插件

四个包构成一个**完整的、官方亲手做出来的"团队插件包"**，这正是我们要做的事的官方样板。

### 1.1 组合关系（不是 4 个独立插件，而是 1 个组合包 + 3 个成员包）

`dsh-experimental-agent-team-profile/package.json` 的 `dependencies` 精确说明了这一点：

```json
"dependencies": {
  "@deepseek-ai/dsh-experimental-tool-agent-team": "0.2.0-rc.2",
  "@deepseek-ai/dsh-experimental-agent-team": "0.2.0-rc.2",
  "@deepseek-ai/dsh-experimental-client-ui-agent-team": "0.2.0-rc.2"
}
```

* `dsh-experimental-agent-team` = **Host 服务**（团队领域：名册 / 邮箱 / 任务板），导出 default 的 `TeamService`。
* `dsh-experimental-tool-agent-team` = **模型工具**（9 个 `spawn_teammate` 等），依赖上面那个服务的 `ctx.agentTeams`。
* `dsh-experimental-client-ui-agent-team` = **浏览器 UI**（成员列表 + 任务看板）。
* `dsh-experimental-agent-team-profile` = **组合包**，运行时内容就是一份 `cordis.patch.yml`；它自己的 `lib/index.js` 是 `export {};`（空模块）。

`dsh-experimental-agent-team-profile/README.zh.md` 原文：

> `cordis.patch.yml` | 叠加在 `dsh-base` 之上的有序 patch
> `src/index.ts` | 空模块入口；patch 是运行时内容

以及：

> **仅显式启用**——本包随安装提供但默认关闭；随附 CLI、Web、SDK、ACP 与 Python profile 都不会启用它。

### 1.2 组合包的 patch 全文（`dsh-experimental-agent-team-profile/cordis.patch.yml`）

```yaml
# Experimental Agent Teams profile layer. Apply after dsh-base so these replacements
# keep direct delegation and coordination on the Team tools.

- id: tool-subagent-control
  disabled: true

- id: tool-subagent-list-agents
  disabled: true

- id: tool-subagent
  disabled: true

- id: tool-subagent-fork
  disabled: true

- insert:
    - id: agent-team
      name: '@deepseek-ai/dsh-experimental-agent-team'
      config:
        maxMembers: 8
        maxTasks: 256
        maxPendingMessagesPerMember: 64
        maxMessageBytes: 65536
        disposalTimeoutMs: 5000

    - id: tool-agent-team
      name: '@deepseek-ai/dsh-experimental-tool-agent-team'
      config:
        freshProvider: spawn
        forkProvider: fork

    - id: ui-agent-team
      name: '@deepseek-ai/dsh-experimental-client-ui-agent-team'
```

**这是"团队工作流插件包"最直接的范本**：`disabled:` 关掉不想要的旧行，`insert:` 挂上自己的服务 / 工具 / UI 三行。

### 1.3 名册（roster）**不是**角色注册表 —— 见 §4

`dsh-experimental-agent-team/lib/types/roster.js`（未压缩源码）里的 `TeamRoster`：

```js
membership(agent) { ... return { root, id: TeamId(root.id), role: 'teammate', name: member.name }; ... }
```

```js
return { root: agent, id: TeamId(agent.id), role: 'lead', name: 'lead' };
```

名册行结构（`list()`）：`{ id, name, role, status, description, provider, context, model, diagnostics }`，其中 `role` 只可能是 `'lead'` 或 `'teammate'`。**没有任何角色目录文件、角色 id、角色定义注册 API。** 详见 §4。

### 1.4 持久化模型（与"台账"最相关的一段）

`dsh-experimental-agent-team/README.zh.md`：

> **持久日志，派生状态。** Lead 会话日志是唯一真源；roster、mailbox 与任务状态每次读取都从中回放。
> **进程内归属。** 所有协作都位于单一进程；保证是重试加去重，绝不是跨进程共识。
> write scope 仅作提示——Bash、formatter、代码生成器与直接外部写入可以绕过文件版本检查
> **共享 checkout**——所有 teammate 都观察同一个工作目录；本 bundle 不提供 worktree 隔离或文件系统锁。

⚠️ 注意：**官方团队插件的台账写在"会话日志"里，不是写在文件里**。我们目前的 JSONL 台账文件是另一条路，见 §3。

## 2. Q1 插件包最小结构与注册 API

### 2.1 `package.json` 需要哪些字段

官方文档 `dsh-agent-preset/skills/cordis-plugin-development/references/host-plugin.md` 给出的**最小 Host-only 组合包**：

```json
{
  "name": "@local/my-plugin",
  "version": "1.0.0",
  "private": true,
  "type": "module",
  "exports": { ".": "./index.js" },
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } }
}
```

> A Host-only bundle needs no dependencies, install scripts, or build tool

**关键判定**：

| 字段 | 是否必需 | 依据 |
|---|---|---|
| `name` / `version` | 必需 | `dsh-package-manifest/README.zh.md`："`DshPackageManifest` 描述 DSH 使用的 package.json 字段，其中 `name` 和 `version` 必填" |
| `type: "module"` | 实操必需 | 所有 4 个参照包都是 ESM；`main`/`exports` 指向 `.js` ESM |
| `dsh.bundle.patch` | **组合包必需** | `host-plugin.md`："A bundle is a package whose `package.json` declares `dsh.bundle.patch`" |
| `dsh.client` | 有浏览器 UI 时必需 | `dsh-client-modules/README.zh.md`："浏览器插件包在其 `package.json` 中以 `platform: 'web'` 声明 `dsh.client`，导出 `./client` bundle" |
| `icon` | 可选 | `host-plugin.md`：插件页卡片与设置清单**不激活插件**就读 `package.json.icon`；SVG/PNG/JPEG/WebP ≤256 KiB，绝对路径/URL/目录外路径/外跳符号链接被拒 |
| `locale/*.json` 的 `meta.title` / `meta.description` | 可选（强烈建议） | 同上；缺失回退到 `package.json` 的 `name`/`description` |
| `engines.dsh` | 可选且**不参与强制** | `dsh-app-boot`："这些检查使用 peer 声明，而不是 `engines.dsh`" |

**`cordis.patch.yml` 是否必须有？** 分两种包：

* **组合包（bundle）**：必须有，并由 `dsh.bundle.patch` 声明。它就是"可安装、可开关、出现在插件页"的单元。
* **裸插件包**：不需要 patch，由**别人**（profile 的 `cordis.patch.yml` 或某个组合包）用 `- insert:` 行挂上。本机现状就是这样：`hooks-claude-code` 不是 bundle，所以只能用 `- insert:` 挂（`~/.dsh/profiles/desktop/cordis.patch.yml` 里的注释也记录了这一点："patch: entry "hooks-claude-code" not found"）。

→ **我们要做的"团队工作流插件包"应该是 bundle**，这样才有 §6 的开关/卸载/插件页卡片。

### 2.2 `lib/index.js` 导出/注册什么

`host-plugin.md` 明确列出**两种互斥形式**：

> `index.js` exports one of these forms; do not mix them:
> - `export function apply(ctx, config) {}` with optional `export const inject = ['tools']` and `export const Config`.
> - A service class as the default export.

**形式 A（函数插件）——实测代码 `dsh-experimental-tool-agent-team/lib/index.js`：**

```js
import z from "@deepseek-ai/schemastery";
import { TeamTaskId } from "@deepseek-ai/dsh-experimental-agent-team";
import { defineTool } from "@deepseek-ai/dsh-tools";

/** Cordis plugin name. */
const name = "tool-agent-team";
/** Services required by the Team tool plugin. */
const inject = ["agents", "agentTeams", "tools", "systemPrompt"];
/** Loader schema for the opt-in Team tool plugin. */
const Config = z.object({
	freshProvider: z.string().default("spawn"),
	forkProvider: z.string().default("fork")
});
// ...
function apply(ctx, config = {}) { /* ... */ }
export { Config, apply, inject, name };
```

**形式 B（Service 类）——实测代码 `dsh-experimental-agent-team/lib/index.js`：**

```js
var TeamService = class extends Service {
	static inject = ["agents","sessions","sessionPersistence","sessionProjections","subagents"];
	static Config = z.object({ maxMembers: z.number().step(1).min(1).default(DEFAULT_MAX_MEMBERS), /* ... */ });
	constructor(ctx, config = {}) { super(ctx, "agentTeams"); /* ... */ }
};
export { TeamError, TeamId, TeamMessageId, TeamService, TeamService as default, TeamTaskId };
```

`super(ctx, "agentTeams")` 把服务注册为 `ctx.agentTeams`。注意 `dsh-experimental-client-ui-agent-team/lib/index.js` 只有 `export { apply }`（连 `name`/`inject` 都不导出）——说明它们都是**可选**的，行 identity 由 patch 的 `id` 决定。

### 2.3 插件如何注册**工具** —— 实际 API 与代码片段

`defineTool` 来自 `@deepseek-ai/dsh-tools`。实测（`dsh-experimental-tool-agent-team/lib/index.js`）：

```js
register(scoped.tools.register(defineTool({
  name: "spawn_teammate",
  description: "Create one named, durable teammate. Only the Team Lead may call this tool.",
  parameters: {
    name:        { type: "string", required: true, description: "Unique lower-kebab-case teammate name." },
    description: { type: "string", required: true, description: "Short description of the delegated responsibility." },
    prompt:      { type: "string", required: true, description: "Complete initial task for the teammate." },
    context:     { type: "string", enum: ["fresh","fork"], description: "..." }
  },
  output: jsonOutput(SPAWN_VALUE_SCHEMA),
  async execute(args, exec) {
    const agent = callingAgent(exec.agent, "spawn_teammate");
    return { member: modelMember((await ctx.agentTeams.spawnTeammate(agent, { /* ... */ })).member) };
  }
})));
```

`output` 的形态：

```js
function jsonOutput(schema) {
  return { schema, render: (_args, value) => [{ type: "text", text: JSON.stringify(value) }] };
}
```

`register` 返回 disposer，插件用 `ctx.effect(...)` 统一释放；`exec` 携带 `exec.agent` / `exec.signal` / `exec.callId`。

**按 agent 作用域注册**（实测 `install(agent, ctx, config)`）：

```js
const scoped = agent.ctx;
scoped.tools.register(...)
scoped.systemPrompt.section({ name: "team:policy", order: scoped.systemPrompt.getSectionOrder("TEAM_POLICY"), text: POLICY });
```

生命周期挂点（实测 `apply`）：

```js
ctx.on("agent/created", ({ agent }) => maybeInstall(agent));
ctx.on("agent/disposed", ({ agent }) => { installed.get(agent)?.(); installed.delete(agent); });
ctx.effect(() => () => { for (const dispose of installed.values()) dispose(); }, "tool-team.scopedTools()");
```

### 2.5 Q1 结论

* 一个 DSH 插件包的**最小结构** = `package.json`（`name`/`version`/`type`/`exports` + `dsh.bundle.patch`，可选 `dsh.client`、`icon`、`locale/`）+ `index.js`（`apply` 或 Service default export）+ `cordis.patch.yml`。
* **注册 API 全家桶（实测）**：`ctx.tools.register(defineTool({...}))`、`ctx.systemPrompt.section({name,order,text})`、`ctx.on(event, handler)`、`ctx.effect(cleanup, label)`、`ctx.slots.inject(key, () => ctx.slots.register(opts, Component))`、`ctx.locale.register(ns, {zh,en})`、`ctx.sessionProjections.register(definition)`、`ctx.commands.register({...})`。
* 客户端 UI 是**独立的浏览器 bundle**，靠 `dsh.client` 声明被 `dsh-client-modules` 发现并经 `/plugins` 提供。**不需要构建工具**——手写 `window.__ModuleLoader__.load` 格式即可（模板为证）。
* `lib/types/roster.js` 的 roster **不是**角色注册表（§4）。

### 3.2 Q2b 判定：**能**

**依据 1：官方文档点名了两个 in-process 拦截机制。**

`dsh-agent-preset/skills/cordis-plugin-development/references/practices.md`：

> **Extension points are shared; use the weakest mechanism that suffices.** From weakest to strongest: `ctx.tools.restrict()` can only remove tools; **`ctx.tools.guard()` can only deny**; waterfall listeners can rewrite and depend on registration order; `system-prompt/assemble` replaces the whole assembly.
> A denial that must hold regardless of order is a **`ctx.tools.guard()`**; a guard is synchronous, so a decision that must await something, such as asking the user, returns `ask` from **`tools/pre-execute`**.
> A waterfall listener (`agent/pre-step`, `agent/request`, `llm/stream`, **`tools/pre-execute`**, `tools/execute`, `tools/post-execute`) that does not own the decision must return `next()`.
> Observe final tool outcomes on `tools/result`; use `tools/post-execute` only to transform a result.

**依据 2：实测 `dsh-tools/lib/index.js` 的 `guard` 定义（`@returns` 明确"返回字符串即拒绝"）。**

```js
/**
* Register a monotonic guard after the extensible `tools/pre-execute`
* waterfall. A plain-context guard applies globally; one registered through
* `agent.ctx` applies only to that agent. Any matching guard may deny by
* returning a reason, while no guard can force-allow a call another guard
* denied. The exact effect disposer is returned for ordered ownership and
* HMR cleanup.
* @param guard - synchronous check; a returned string denies the execution.
* @returns the exact disposer that unregisters the guard.
*/
guard(guard) {
  return this.layers.effect(this.ctx, (layer) => layer.guards.append(guard), { label: "tools.guard()", notify: false });
}
```

**依据 3：实测 waterfall + 决策形状（同文件的 `prepareExecution`）。**

```js
const carrier = scopeTarget(this, exec.agent);
const gate = await this.ctx.waterfall(carrier, "tools/pre-execute", exec, () => Promise.resolve({ kind: "allow" }));
const askResolution = gate.kind === "ask" ? await this.serviceAsk(exec, gate) : { decision: gate, approvalCancelled: false };
const { decision } = askResolution;
if (decision.kind === "cancel") return await next({ kind: "post-result", exec, result: toolAbortedBeforeDispatchResult() });
const denialReason = decision.kind === "allow" ? this.guardReason(exec) : decision.reason;
const denialInfo = decision.kind === "deny" ? decision.info : void 0;
if (denialReason !== void 0) return await next({ kind: "post-result", exec,
  result: this.materializeFinalResult({ content: [{ type: "text", text: `Error: ${denialReason}` }],
    isError: true, error: { message: denialReason, ...(denialInfo === undefined ? {} : { info: denialInfo }) } }) });
```

### 4.3 Q3 结论与可选路径

**判定：我们的 10 个角色不能注册成 DSH 一等公民。** 依据：不存在角色注册表（§4.1 证据 1–3）；preset 是会话级且子 agent 强制加入父 preset（证据 4）。

可选路径（按代价排序，均**未实测**）：

| 方案 | 做法 | 得到 | 失去 |
|---|---|---|---|
| A（现状） | 角色 = teammate 名 + `roles/<name>.md` 全文写进 `prompt` | 零成本、今天就能用 | 角色不是机器可读概念；工具面无法按角色收窄 |
| B | 自建插件注册自己的 `spawn_role_teammate` 工具，直接调 `ctx.subagents.startContinuable({ ..., request: { prompt, parent, persona, toolFilter } })` | 真正的 per-角色人设 + **工具面隔离**（可直接替掉 `denied_paths` 那套） | 拿不到 agent-team 的持久名册 / mailbox / 任务板 / Team UI |
| C | 自建插件实现"角色目录服务"（读 `~/.dsh/roles/*.md` + `registry.yaml`，暴露为 `ctx.roles` 与只读工具），但**仍用 `spawn_teammate`** 派发 | 角色可枚举、可校验、可被 UI/命令读取；与现有团队栈兼容 | 只能注入到 `prompt` 文本；工具面隔离仍需另想办法 |
| D | 为每个角色做一个 agent preset | preset 能改人设+工具 | **不可行**：preset 是会话级，一个会话只能选一个 |

→ **推荐 C（+ 在需要时叠加 B 的工具面能力）**：把角色目录做成一等公民的**插件服务**（这是我们能造出来的"准注册表"），派发仍走原生 `spawn_teammate`。

## 6. Q5 打包、安装与版本约束

### 6.1 发现机制

* **发现的真源是 Cordis Loader 条目**，而不是 npm 目录扫描或白名单。
  `dsh-host-plugin-inventory/README.zh.md`："每一行是一个非组 Loader 条目：其条目 id、精确模块标识、有效启用状态……每次 `list()` 调用都读取 `ctx.loader.entries()`"。
* **组合来源**（`dsh-app-boot/README.zh.md`）：
  > profile 位于 **`$DSH_HOME/profiles/<name>`**，由可安装组合包和自身 `cordis.patch.yml` 组成。组合包的 `dsh.bundle.patch` 指定一个 patch 文件或一个有序的文件列表……
  > **`cordis.patch.yml`**——你的 tweak 层，应用在所有组合包层之后（先应用逐 profile 的文件，再应用 home 级文件，因此**后者优先级更高**）
* **组合包列表** = profile `package.json` 的 `dsh.profile.bundles`（本机实测：见 §0.1）。
  `dsh-plugin-manager/README.zh.md`："组合包开关修改 `package.json` 的有序 `dsh.profile.bundles` 列表。"
* `dsh-plugin-package-inventory-deepseek` **不是白名单**——它是发给 DeepSeek 官方 API 的请求元数据（`dsh_plugin_packages` 字段）；"系统会排除禁用、pending、failed、disposed、unloading 状态，结构性 `cordis:` 配置项，**普通依赖**，没有所属包身份的松散文件，以编程方式挂载的子 fiber，以及内存动态插件"。**没有任何"只允许 `@deepseek-ai/*`"的机制。**

### 6.2 是否必须是 npm 包 / `name` 能否指向本地路径 → 判定：**能**

**证据 1：官方文档直接把"绝对包目录"写成安装 target。**
`cordis-plugin-development/SKILL.md`：

> For implementation, use ordinary workspace files to author a bundle, then **`plugin_manager` with `action: install_bundle` and the absolute package directory as `target`** to install it in the current profile. Changes affect every session in that profile and survive restart.
> Do not write the profile's `package.json` or `cordis.patch.yml`, create packages under `$DSH_HOME`, or run pnpm in the profile directory: **`install_bundle` performs those steps**

**证据 2：`parseInstallSpec` 实测接受绝对路径与 `file:`/`link:` 前缀，且显式拒绝相对路径。**

`dsh-plugin-manager/lib/types/install-spec.js`（关键片段）：

```js
export function parseInstallSpec(raw) {
    const spec = raw.trim();
    if (spec === '') throw invalid(spec, 'the package spec must not be empty');
    const path = spec.replace(/^(?:file|link):/, '');
    if (path !== spec || isAbsolute(path)) {
        if (!isAbsolute(path)) throw invalid(spec, 'a local path must be absolute');
        return TARBALL_SPEC.test(path) ? { kind: 'tarball', spec, path } : { kind: 'path', spec, path };
    }
    if (/^\.{1,2}(?:[\\/]|$)/.test(spec)) throw invalid(spec, 'a local path must be absolute');
    ...
    return range === undefined ? { kind: 'registry', spec, name } : { kind: 'registry', spec, name, range };
}
```

其 JSDoc：

> Read a spec into its form. **A path must be absolute**: the Host's working directory means nothing to the person typing into a browser, and a relative path resolved against the profile would point inside it.

**证据 3：本地路径被明确排除在"GitHub 预检"之外，并会**直接读 `package.json`** 做兼容性判定。**
`dsh-plugin-manager/README.zh.md`：

> `installBundle` 在启动 pnpm 前通过 `git ls-remote` 检查 GitHub 仓库……
> **注册表包、本地路径、压缩包和其他 Git 主机跳过此检查。**
> `inspect(spec, options)` 在任何东西安装之前读出 spec 指向什么：注册表包名通过 `pnpm view` 询问注册表……**绝对路径读取其 `package.json`**……
> 点名软件包的安装命令（`add`，或带 spec 的 `install`）会在 pnpm 运行前完成检查：**本地路径直接读取其 `package.json`**

**证据 4：`plugin_manager` 工具的 `target` 语义里就包含"installation spec"。**
实测 `dsh-plugin-manager/lib/types/tools.js`：


⚠️ **注意（未完全证实）**：`installBundle` **仍然会调用 pnpm**（`pnpm add --registry ...` 在 profile 目录里执行）。本机实测 `pnpm` **不在 PATH 上**，但 **DSH Desktop 应用自带 pnpm**：

→ 一个**零依赖**的本地 bundle（形如官方最小 manifest）大概率能离线装成（pnpm 对 `kind:'path'` 的 spec 不需要 registry，且 profile 的 `pnpm-workspace.yaml` 已设 `autoInstallPeers: false`）。但**我没有实测安装**，因此"完全离线可装"标记为**未证实**。

### 6.3 profile 结构与 patch 语义

* 位置：`$DSH_HOME/profiles/<name>`（本机：`/Users/maxwell/.dsh/profiles/desktop`）。
* 文件：`package.json`（`dsh.profile.bundles` 有序列表）、`cordis.patch.yml`（用户 tweak 层）、`cordis.yml`（根，实测内容为 `[]`）、`pnpm-workspace.yaml`、`node_modules/`（安装后才有）、可选 `compatibility.json`、`.plugin-manager/`。
* patch 方言（`host-plugin.md`）：
  > Read an existing patch before editing it: **a matching override replaces the complete `config`**.
  > `- insert:` 下每条 `{ id, name, config }`；`disabled: true|false`；`!!js` 表达式可用。
  `dsh-app-boot`：按 id 定位的 patch **不做深度合并**，覆盖必须重述要保留的字段。
* **开关语义**（`dsh-plugin-manager/README.zh.md`）：
  > 插件开关只更新 profile 的 `cordis.patch.yml` 中**最后一条匹配覆盖项**的 `disabled`；没有匹配项时追加。匹配依据是**条目 id，以及覆盖项声明的模块名称**。
  > **组合包开关修改 `package.json` 的有序 `dsh.profile.bundles` 列表。** 关闭保留依赖；开启追加到列表末尾，可能改变配置优先级。**安装新组合包默认启用。**
* 层级优先级：bundle 层（按 `dsh.profile.bundles` 顺序）→ profile `cordis.patch.yml` → home 级 patch（**最高**）。

### 6.4 版本约束机制 → **有**，但 **未声明 DSH peer 依赖时不受约束**

`dsh-app-boot/README.zh.md`（最权威的一段）：

> profile 导入插件前，DSH 会检查其 **`peerDependencies`** 中对 `@deepseek-ai/dsh` 和 `@deepseek-ai/dsh-*` 的依赖，与 **`getDshRuntimeVersion()`** 返回的唯一运行时版本比较。**每个声明的版本范围都必须匹配**；**预发布版本参与范围匹配**。源码工作区的 `workspace:^`、`workspace:~`、`workspace:*` 指向同一个运行时。**未声明 DSH peer 时不施加版本约束**；无效范围视为不兼容。这些检查**使用 peer 声明，而不是 `engines.dsh`**，也不是防范恶意包代码的沙箱。

以及：

> 组合包本身不是行，因此 `loadProfileDirectory` 在启动和每次重新组合加载 profile 的组合包层时，检查**每个组合包自己声明的 DSH peer**；没有豁免的不兼容组合包会像无法读取的组合包一样被跳过，并列入 `skippedBundles`。
> 精确版本豁免保存在 profile 自己的 **`compatibility.json`** 中……它把精确的 `package-name@version` 键映射到精确 DSH 运行时版本列表；**插件升级和 DSH 升级都不继承授权**。

工具/CLI 面（实测 `dsh-plugin-manager/lib/types/tools.js`）：

```js
action: { enum: ['list_plugins','list_bundles','set_plugin','set_bundle','install_bundle','remove_bundle',
                 'list_version_exemptions','set_version_exemption'] },
runtimeVersion: '... For set_version_exemption: exact DSH version from list_version_exemptions. Target must be the manifest package-name@version, not an alias or version range.',
acceptRisk: '... true only after warning the user about possible crashes and data loss and receiving explicit permission for this exact plugin/runtime pair.'
```

工具 `description` 亦声明：`Incompatible DSH peer dependencies block installation and activation.`

**这对我们的直接战略含义**：
若插件**只写 `node:fs` / `node:path`，不 import 任何 `@deepseek-ai/dsh-*`**，则**声明零 DSH peer**，于是 `0.2.0-rc.2 → 未来版本` 的升级**不会**被兼容性检查拦下，也就免疫了 RC 内部 API 漂移。这是一个**巨大的降风险杠杆**。
代价：拿不到 `ctx.tools` / `ctx.commands` / `ctx.slots` 这些能力。所以现实必然是**混合**：功能插件声明 peer（耦合 RC），纯数据/台账逻辑抽成零依赖工具库。

另外 `dsh-package-manifest/README.zh.md` 列出可选元数据字段：
* `dsh.manifestVersion`（声明的格式为 `1`）
* `engines.dsh`（作者声明的兼容范围；**不参与强制**）
* `PluginLocalizedMeta`：`package.json.icon` 解析出的 data URL + 元信息诊断

### 6.5 安装流程 & bundle vs plugin

`dsh-plugin-manager/README.zh.md`：

> 服务与 `dsh plugin` 共用 [operations.ts] 中的包管理操作。
> CLI 提供 `dsh plugin --profile <profile> ...`
> 运行以进程退出为完成点……每次操作把它启动的 pnpm 运行记录在 `.plugin-manager/run.json` 中
> 失败或被取消的安装会恢复 pnpm 运行前快照的 manifest 与 lockfile
> pnpm 11 拦下依赖脚本时，失败的安装在 `pendingBuilds` 里报告……工具可以在用户于对话中批准这些脚本后，通过 `install_bundle` 的 `approvedBuilds` 代为授权
> 安装按 request id 跟踪到调用结束

| | bundle（组合包） | 裸插件 |
|---|---|---|
| 声明 | `package.json` 的 `dsh.bundle.patch` | 无 |
| 出现在插件页 | **是**（"已安装"分区，带卡片/图标/描述） | 只有被某个 bundle 的 patch 行 `insert` 后，才作为**行**出现在该 bundle 详情里 |
| 可开关 | **是**（`dsh.profile.bundles`） | 行级 `disabled` |
| 可卸载 | 是（`remove_bundle`） | 否（属依赖，不能启用） |
| 安装方式 | `plugin_manager install_bundle` / `dsh plugin --profile X add <spec>` | 手写 patch 行（本机 `hooks-claude-code` 即如此） |

**实测 `dsh-client-ui-plugin-manager/README.zh.md`**（插件页行为）：
> 在侧栏选择**插件**。……**官方**排在前面，列出安装随附、供开启的组合包……**已安装**列出 profile 持有的组合包。
> 已安装的组合包及其插件行在卡片和详情页中，按当前界面语言显示各自的标题与描述。每个字段**先读取导出的 locale `meta`，缺失时回退到该插件地址下可访问的 `package.json`**；标题最终使用完整包名或模块名

→ **这正是"出现在 DSH 插件管理器里、能开关/版本化"的落地目标，且已被证实可达。**

### 6.6 Q5 残余不确定

* `install_bundle` 对本地绝对路径是否**真的能完全离线**完成（pnpm 是否会因 workspace/lockfile 而去碰 registry）：**未证实**（本机没跑过安装，且遵守"不得安装依赖"的约束）。
* `dsh plugin --profile desktop add /abs/path` 与 `plugin_manager install_bundle` 是否对本地路径完全等价：**未证实**（只读了文档，二者共用 operations.ts 的表述来自 README）。
* 插件页对"本地路径安装的 bundle"是否与"官方 bundle"同样渲染卡片（含 `icon`/locale meta）：README 说"已安装的组合包及其插件行……显示各自的标题与描述"，倾向于是，但**未实测**。

## 7. 总体判断与建议

### 7.1 判定：**值得做**，但必须分阶段、并把"角色"这一块降级预期

**确实能拿到的（证据充分）**

1. **一个真正可安装、可开关、可版本化的插件包**（`dsh.bundle.patch` + `dsh.profile.bundles`），出现在 Web 插件页，带标题/描述/图标。本地绝对路径即可安装，不需要真发包。
2. **进程内写台账**（`<workspace>` 与 `~/.dsh`），不再受 Seatbelt 只读沙箱限制 —— **这是本次勘察价值最高的一条**：目前"Lead 预写 + 钩子只读校验"的妥协**可以彻底去掉**。
3. **进程内工具调用拦截与阻断**（`tools/pre-execute` waterfall 的 `deny`/`ask`/`cancel`，或 `ctx.tools.guard()` 的单调拒绝），决策以 `Error: <reason>` 呈给模型。
4. **agent 作用域的工具面隔离**（`ctx.tools.restrict({allow,deny})` on `agent.ctx`）—— 可以直接把"QA 不得修改被测实现"从"路径黑名单 + 钩子 exit 2"升级为"工具级不可见"。
5. **斜杠命令**（`ctx.commands.register`，宿主进程内运行，不产生模型消息；以及客户端 `ctx.commandUi` 的弹窗/动作/装饰）。
6. **GUI 状态面板**（`ctx.slots.inject` + `ctx.slots.register`，44 个已声明 slot 可选，`conversation.session.header.actions` 是现成先例）。
7. **原子写 + 跨进程写锁**（`dsh-atomic-write` 的 `writeFileAtomic` / `withFileLock`），可用于台账完整性。
8. **`~/.dsh` 路径解析库**（`dsh-home-paths`）。

**拿不到的 / 要降级预期的**

1. **角色不能成为一等公民。** 没有角色注册表；`role` 只有 `lead`/`teammate`；`spawn_teammate` 的角色就是名字 + 提示词文本；teammate 强制加入 Lead 的 preset，preset 是会话级的。→ 只能做**自建角色目录服务**（并可选地叠加 per-child `persona` + `toolFilter`）。
2. **不能给 teammate 独立 worktree / 文件锁**（官方团队包自己也不提供；这是上游未实现的方向，README 明确列为"未来方向"）。
3. **不能把裸 `hooks.json` 那种"任意 command hook"变成原生的**——原生插件拿到的是 harness 扩展点，行为要重写，但功能是**超集**。
4. **面板显示台账**这一步需要额外设计（投影需会话事件派生 / Remote 需生成产物），不是白拿。

### 7.2 建议分阶段

**Phase 0（1 天内可验证，零风险）**
* 用官方模板（`templates/decoration/`）做一个**最小零依赖 bundle**：一个 `index.js` + `cordis.patch.yml` + `package.json`，`apply()` 里只做一件事——向 `~/.dsh/team/ledger/` 原子追加一条记录。
* 用 `plugin_manager({action:'install_bundle', target:'<abs path>'})` 装入 `desktop` profile，确认：① 出现在插件页；② 可开关；③ 能写 `~/.dsh`。
* **这一步同时验证了 §6.6 的两个未证实点**（本地路径离线安装、插件页渲染）。

**Phase 1（核心价值）**
* 把 `policy_check.js` 的策略逻辑搬进插件，注册 `tools/pre-execute` 监听（或 `ctx.tools.guard()`）+ `agent/pre-execute`。
* 台账改由插件**进程内原子追加**，取消"Lead 预写"。
* 路径隔离改用 `agent.ctx.tools.restrict({ deny: ['write','edit'] })` 施加于 QA/审查 agent，替代或叠加现有 `denied_paths`。
* 保留 `dsh-hooks-claude-code` 作为**回退路径**（两者可共存，注意 deny 折叠：`deny > ask > allow`）。

**Phase 2（可观测性）**
* 注册一个 `/team` 或 `/ledger` **Host 命令**，输出台账摘要 + 门状态（走 `dsh-commands`，无模型消息）。
* 加一个面板：先做**最简单可行版本**——把状态渲染在 `conversation.session.header.actions`（照抄 agent-team 的做法）。数据通道**优先试会话投影**（把台账关键状态同时折叠进来），Remote 作为备选（需确认生成产物能否手写）。

**Phase 3（角色）**
* 实现自建角色目录服务 `ctx.roles`：读 `~/.dsh/roles/*.md` + `registry.yaml`，暴露为只读工具（`list_roles` / `get_role`），并让派发工具自动把角色文本注入 `prompt`。
* 若 Phase 1 的 `restrict` 路径验证良好，可进一步提供自建 `spawn_role_teammate`（走 `startContinuable` + `persona` + `toolFilter`）作为"强隔离角色"选项。

**不建议做的**
* 不要试图把 10 个角色做成 agent preset（会话级，做不到 per-teammate）。
* 不要把整包绑定到 `@deepseek-ai/dsh-experimental-*` 的内部类型上（见 §8）。
* 不要在插件里自己写 profile 的 `package.json` / `cordis.patch.yml`（`SKILL.md` 明确要求交给 `install_bundle`）。

### 8.2 风险（按严重度）

1. **版本耦合（最高）**。`0.2.0-rc.2` 是 RC；一切 `ctx.*` 服务与事件名都可能变。
   * 缓解 ①：**零 DSH peer 依赖**的子包不受 §6.4 的兼容性检查约束（"未声明 DSH peer 时不施加版本约束"）→ 把纯逻辑（台账读写、合同校验、门状态计算）抽成**零依赖库**，让薄薄的功能插件承担耦合。
   * 缓解 ②：所有内部 API 调用点集中到少数几个文件，便于升级时改。
   * 对照数据：4 个官方实验包把 `@deepseek-ai/dsh-*` 全部写成 `"0.2.0-rc.2"`（**精确版本，不是范围**），说明官方自己也按精确版本绑。
2. **实验包不承诺稳定**。`dsh-experimental-agent-team` 的 README 明写"实验原型，无稳定性承诺"，且 `dsh-experimental-agent-team-profile` 是"随安装提供但**默认关闭**"。我们的插件若依赖 `ctx.agentTeams`，就依赖了一个明确不稳定的服务。
3. **客户端 bundle 是手工产物**。必须随包发布符合 `window.__ModuleLoader__.load` 格式的 `lib/client.js`；`dsh-client-modules` 会拒绝畸形请求、缺失提供方、自请求与同步请求环；`practices.md` 禁止 require 任何 Harness Client 包。手写正确性靠人工与实测，**一次写错 = 槽位崩溃 = 面板空白**（console: `slot entry crashed in '<slot>'`）。
4. **安装需提权**。"每个工具操作都要求 `danger-full-access` 或本次调用的批准"；审批渠道不可用/被拒绝/取消时**不执行**。且"installed Host code runs outside the workspace sandbox"——一旦装上，插件写文件**不再经过那套审批**。这是**治理上的真实权限扩张**，必须让用户显式知情。
5. **`cordis.patch.yml` 覆盖是整体替换**。"a matching override replaces the complete `config`"、"不做深度合并，因此 profile 覆盖必须重述需要保留的组合包字段"。插件开关逻辑依赖"最后一条匹配覆盖项"的 `disabled` 字段，用户手工编辑容易踩坑。
6. **原地替换已安装包需要重启**。"替换已有包后需要重启进程，以加载新的 JavaScript 模块版本"、"manifest 身份会在进程存活期内缓存"。HMR 只能覆盖"新 bundle 首次激活"与 patch 变化。
7. **`0.2.0-rc.2` 的兼容性豁免是双刃剑**。`set_version_exemption` + `acceptRisk: true` 可以让不兼容插件上线，但工具的 `description` 原话是 "Version exemptions risk crashes and data loss"；且"插件升级和 DSH 升级都不继承授权"——每次升级都要重新授权。
8. **本机 sidebar 上的既有耦合**。`~/.dsh/profiles/desktop/package.json` 里 `dsh.profile.bundles` **已经**包含 `@deepseek-ai/dsh-experimental-agent-team-profile`；我们的插件若替换/禁用它（例如用插件版 `spawn_teammate` 替代内置的），会与 §6.3 的"组合包开关追加到列表末尾，可能改变配置优先级"交互，需谨慎。

## 10. 一句话总结

**值得做。** 按本次勘察，插件化能拿到的**最关键三项**——进程内写台账、进程内拦截阻断工具调用、本地路径安装为可开关的 bundle——都有明确且充分的证据；**唯一必须降低预期的是"角色"**：DSH 没有角色注册表，角色只能是"名字 + 提示词"，要成为一等公民只能由我们自建（可叠加 per-child `persona`/`toolFilter` 接缝）。主要风险是 `0.2.0-rc.2` 的 RC 内部 API 漂移，缓解手段是把纯逻辑抽成**零 DSH peer 依赖**的子包（未声明 DSH peer 时 DSH 不施加版本约束），把耦合集中在薄薄的功能插件层。

## 11. 更新（2026-10-14）：页头卡片已移除，UI 归官方

在本文件成文之后，插件曾自带一张「角色分工」页头卡片——官方
`dsh-experimental-client-ui-agent-team` 客户端 bundle 的逐字副本，只换了文案与数据。
**该卡片已整体移除**，原因是它与官方插件抢同一套注册坐标：

| 坐标 | 官方 | 本插件（移除前） |
|---|---|---|
| locale 命名空间 + 键 | `agent-team` + `{zh,en}` | 同 |
| list slot id | `agent-team` @ `conversation.session.header.actions` | 同 |
| order / priority | `-20` / 0 | 同 / 同 |
| CSS 类名前缀 | `_2tNPVa_` | 同 |

两插件的 `apply` 都是**先 `locale.register`、后 `slots.inject`**，所以第二个 apply 首先在 locale 抛错
（`locale namespace "agent-team" already has locale "zh"`，`dsh-client-locale/lib/client.js:1387-1414`）；
slot 的 `already has an entry with id` 只有在 ns 改名后才会轮到。
`immediately` 只是预取 tier、不保证 apply 顺序（浏览器侧 `Promise.all` 并发建 entry），
而 `order` ≠ `priority`：判重只看 id + priority，不同 priority 可共存但每 id 只渲染最低 priority 那个。
**所以只改 slot priority 修不好这个冲突。**

后果比"少一张卡片"严重：客户端 entry 的 apply 一抛，Web 外壳的启动激活审计
（`web boot: N entries did not activate`）在 `uiRenderer.mount()` 之前 throw →
**整个 Web 客户端不挂载**，停在 `Failed to load plugins`；桌面端弹恢复对话框并写崩溃报告。
更坑的是真实异常**既不在 console 也不在 boot 页**（浏览器合成里 cordis logger 只有 1000 条内存环形缓冲、
无 exporter），console 只剩 `<包名>: failed`。

卡片还有第二层问题：数据源被换成静态 `workflowRoster()`（10 个角色写死、`phase: "active"`、
成员行 `disabled: true`），**完全没接 `useSessionStatus`**，所以哪怕它自己渲染出来也不显示真实运行状态。

**现状（2026-10-14 最终形态）**：页头卡片以**官方客户端 bundle 为外壳**（观感照搬官方），内容换成
10 个角色名册并把角色与成员对应起来显示真实状态；**让位方式 = 同槽位遮蔽**（用户裁决"机制甲"）：
slot id 与 order 与官方相同、`priority: 100` 高于官方默认 0，官方启用时本插件被 DSH 自动遮蔽、
官方关闭时自动接管——**不是并存**。locate ns `dsh-team-workflow` / CSS `_twf_` / 模块 id 自有。
产物由 `_tools/build-client.js` 生成（18 组补丁，硬断言守门）。设计与决定见
`dsh-team-plugin/CONSTITUTION.md`（19 条 + 违宪记录），第一版（沿用官方坐标）留在
`_tools/retired/` 作事故档案。

按用户 2026-10-14 的决定，**团队角色的默认派发通路是 `spawn_teammate`**：
官方团队面板的数据源 `agentTeam` 投影只收录 `spawn_teammate` 创建的成员，用 `subagent` 派发的子会话
不进成员列表，"成员运行状态"就永远是空的。策略层（`policy_check.js` 的 `DISPATCH_TOOLS` /
`ALWAYS_GATED_DISPATCH`、`hooks.json` 的三个 matcher）**早已包含 `spawn_teammate`**，
缺的只是规则与文档这一层；规则现在写在 `instructions/AGENTS.md`（**被 install.sh 安装到
`~/.dsh/AGENTS.md` 的源**——手改安装后的副本会被下次安装覆盖，2026-10-14 实际丢过一次），
门 `7a/7b` 盯住。

回归门 `6a–6g` 的判据随宪法（`dsh-team-plugin/CONSTITUTION.md`）走，当前 **24/24**。
2026-10-14 用户裁决"让位用同槽位遮蔽"（机制甲）后，判据**又变了一次方向**：
slot id 不再是自有坐标，而是**故意与官方相同**、靠 `priority` 决定谁渲染：

补充（同日本轮逆向，第三方若要做卡片必须知道）：

- `agentTeam` 投影的 `members[]` **只有 5 个字段**：`id / name / role / phase / error`；
  `model`、`provider`、`description` 等在 durable state 里有，但**被 wire view 有意剔除**，
  第三方要拿只能走 `agentTeams.listMembers()` RPC。
- 成员运行状态是两条正交通路：`useSessionStatus`（客户端本地镜像）与
  `useSessions.byId[id].running`（host 列表快照），官方写成 `running ?? summaryRunning`
  （`??` 而非 `||`），且 `useSessionStatus` 的键可能整体缺失，必须 `?.`。
- selector 走 `useSyncExternalStoreWithSelector` + `Object.is`，**不得在 selector 里 `.map()/.filter()/造对象`**，
  否则无限重渲染。
