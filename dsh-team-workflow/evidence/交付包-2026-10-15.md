## 1. 官方导入渠道（读官方包确认，不是印象）

来源：`app.asar/dsh/node_modules/@deepseek-ai/dsh-plugin-manager`（package.json 描述：*"plugin and bundle management shared by dsh CLI, Web and agent tools"*）。

- 三条通路：**Web 侧栏 Plugins 页** / **`plugin_manager` agent 工具（Creator 模式）** / **`dsh plugin` CLI**。
- 接受的 spec（官方 README 的 `inspect` 段）：**注册表包名 | 绝对路径 | git 地址 | tarball**。
- 「安装新 bundle 默认启用」→ 实测确认见 §3。因此接收方**不需要**手改 `dsh.profile.bundles`。

CLI 语法取自真入口 `--help`（**不是猜的**）：

```
Usage: dsh [--profile] <name> [options] [app-args...]
       dsh plugin --profile <name> <pnpm-args...>
Examples: dsh plugin --profile tui add <package>    install a plugin into the tui profile
```

CLI 实机入口（本机没装 `dsh` 命令，直接用应用自带的）：

```bash
APP="/Applications/DeepSeek Harness.app"
CLI="$APP/Contents/Resources/app.asar/dsh/node_modules/@deepseek-ai/dsh-desktop-host/lib/cli.js"
ELECTRON_RUN_AS_NODE=1 "$APP/Contents/MacOS/DeepSeek Harness" --expose-internals "$CLI" --help
```

GUI 输入框的官方措辞（取自 `dsh-client-ui-plugin-manager/lib/client.js`）：

- 标签：「包名或地址」；说明：「输入插件的包名、GitHub 仓库地址或本地目录路径。」
- 校验失败文案：「请输入有效的包名或地址」；另有「.tgz 直链」路径的专门提示。

## 3. 官方渠道端到端验证（隔离 DSH_HOME，不碰用户 profile）

沙箱：`DSH_HOME=<tmp>/home`，`profiles/delivery/package.json` 为**干净起点**
（`dependencies: {}`，`bundles` 只有官方的 `@deepseek-ai/dsh-base` + `@deepseek-ai/dsh-web-app`）。

### 3.1 tarball spec

```bash
DSH_HOME="$SB" ELECTRON_RUN_AS_NODE=1 "$APP/Contents/MacOS/DeepSeek Harness" --expose-internals "$CLI" \
  plugin --profile delivery add "$OUT/local-dsh-team-workflow-0.3.0.tgz"
```

输出：`+ @local/dsh-team-workflow file:…/local-dsh-team-workflow-0.3.0.tgz`、`Packages: +4`、`Done in 215ms using pnpm v11.7.0`。

装后 `profiles/delivery/package.json`：

```json
"dependencies": { "@local/dsh-team-workflow": "file:…/local-dsh-team-workflow-0.3.0.tgz" },
"dsh": { "profile": { "bundles": ["@deepseek-ai/dsh-base","@deepseek-ai/dsh-web-app","@local/dsh-team-workflow"] } }
```

→ **bundle 自动登记并启用**（实证 §1 的官方说法）。profile 目录新增 `.plugin-manager/`、`pnpm-lock.yaml`、`node_modules/`。

装出来的副本与交付目录**逐字节一致**（sha256 全同）：`index.js`、`client.js`、`roles.json`、`package.json`、`locale/zh.json`、`cordis.patch.yml`。

### 3.2 本地目录 spec（发现关键差异）

```bash
… plugin --profile delivery add "$OUT/dsh-team-workflow"
```

输出：`+ @local/dsh-team-workflow link:…/dsh-team-workflow`，**没有 `Packages:` 行** → pnpm 未安装任何依赖
（`link:` 语义），profile 里是个**符号链接**，`node_modules/@deepseek-ai/schemastery` 不存在。
此时实测导入：

```
导入失败： ERR_MODULE_NOT_FOUND Cannot find package '@deepseek-ai/schemastery'
          imported from /Users/maxwell/Desktop/dsh-team-workflow-交付包/dsh-team-workflow/index.js
（退出码 3）
```

→ 若照 GUI 输入框提示的「本地目录路径」交付，接收方会拿到一个**加载不起来**的插件。

### 3.3 修法：交付目录自带依赖（已在交付物上生效）

```bash
cd "$OUT/dsh-team-workflow"
"$NODE" "$PNPM" install --prod --config.node-linker=hoisted --config.auto-install-peers=false
# Packages: +3 … Done in 220ms  → node_modules/@deepseek-ai/{schemastery,cosmokit} + @standard-schema（真实目录，非 .pnpm 符号链接）
```

重装同一目录 spec 后复测：

```
导入成功 ✓  plugin.name = team-workflow | 配置字段数 = 6      （退出码 0）
```

### 3.4 组合结果（证明补丁层真的挂上、且条目 id 与包名无关）

```bash
… --profile delivery --dump-config | grep -A2 "team-workflow"
# == @local/dsh-team-workflow
# - id: team-workflow
#   name: '@local/dsh-team-workflow'
```

`id: team-workflow` 来自插件导出的 `name`（客户端配置寻址用的就是这个 id），**与包名无关**。

### 3.5 卸载

```bash
… plugin --profile delivery remove @local/dsh-team-workflow
```

→ `dependencies` 清空、`bundles` 回到只有官方两个、`node_modules/@local/dsh-team-workflow` 消失。
**官方 remove 会同时摘掉依赖与组合包登记**（文档里的卸载说明据此写）。
