决定
----
用户先选「只留官方入口」（把客户端半侧整体删掉），随后发现其代价：
**官方插件一关，页头就没有本插件的入口**。于是改为**自有身份并存卡片**。

坐标（全部自有，与官方零重叠）
------------------------------
| 坐标 | 本插件 | 官方 |
|---|---|---|
| slot id | team-workflow | agent-team |
| locale ns | dsh-team-workflow | agent-team |
| CSS 前缀 | _twf_ | 它自己的哈希前缀 |
| order | -19 | -20 |
| module id | @local/dsh-team-workflow | @deepseek-ai/dsh-experimental-client-ui-agent-team |
| 服务 inject | slots, locale | sessions, uiWorkspace, slots, locale |

`inject` **故意不声明 `sessions`**：本卡片只用会话标准 props（由父级 render 调用点注入），
不需要该服务。少一个 inject 就少一条 "pending (waiting for service)" 风险——
而 pending 同样会让启动激活审计 throw，一样是整页失败。

卡片**确实挂载了**（boot 没崩，说明坐标方案成立），但 21 条 CSS 规则全部无效。
两个根因，各自独立：

BUG 1（样式全错 + 展不开）
  CSS 模板写成 `${CSS_PREFIX}root{...}`，拼出来是 `_twf_root{...}`——
  这是**元素选择器**（去找 <_twf_root> 标签），不是类选择器。官方是 `._2tNPVa_root`。
  后果：面板没有 position:fixed（useAnchoredPosition 算出的 left/top 全废）、
  没有 z-index、没有背景；面板量不到尺寸，一直停在 `visibility:hidden` 兜底态。
  修法：生成器改用 S() 包装类名，把前导点放在调用处（不再靠人记得）。

BUG 2（点不开 / 闪一下就没）
  面板是 createPortal 到 document.body 的，**不在 rootRef 里**。我只给 root 接了
  onMouseLeave，没给面板接 onMouseEnter/onMouseLeave。鼠标从按钮移向面板时，
  root 的 onMouseLeave 先触发 → 面板被关掉。
  修法：照官方已验证实现，给面板自己接 onMouseEnter: cancelHover / onMouseLeave: scheduleHoverClose；
  同时把悬停展开从"wrapper 的 onMouseEnter"改到"button 的 onMouseEnter"（官方位置），
  并加上官方的"窄容器下标签 display:none 就不靠悬停展开"守卫。

新增两道回归门（都做了独立反证）
  6e  CSS 选择器合法且全部带自有前缀
      → 删掉前导点：报 25 条非法/越界选择器 FAIL
  6f  渲染冒烟：用真实产物 + 桩 React 真渲染一遍组件，断言
      · 名册渲染出 10 行（不是空壳）
      · 面板元素上必须有 onMouseEnter + onMouseLeave（悬停保活）
      · 面板 style 必须接上 useAnchoredPosition 的结果
      · position 为 null 时必须退到 visibility:hidden 兜底
      · 渲染树里每个 class 都必须在 CSS 里有对应规则（交叉校验，防类名漂移）

机制实测（_tools/probe-slot-shadowing.js，真实 SlotCore，结论可复现）：
  槽位 conversation.session.header.actions 是 **list** 槽，id 决定「格子」，每个格子只渲染一个胜出者；
  胜出者按 (priority ?? 0) 升序取第一个。因此：
    · 同 id + 不同 priority → 不抛，2 条记录但只有 1 个胜出（官方默认 priority 胜出）
    · 加载顺序无关：先注册我方、后注册官方，官方仍然胜出
    · 官方缺席 → 我方胜出（官方关闭即时接管，靠注册表通知重渲染）
    · 同 id + 同 priority → 抛 "already has an entry with id" —— 第一版整页起不来的真正原因
    · 不同 id（当前实现）→ 2 个胜出 → 两张卡片并存 → 违反 C1
  已知官方注册参数：{name, id:"agent-team", order:-20, locale:NS, inject}（无 priority ⇒ 默认 0）

→ 因此 C1 有两种实现，机制完全不同，需用户裁决（宪法 C3 slot id 那一行是否修订）：
   甲「同槽位遮蔽」：同 id + 更高 priority + 注册外包 try/catch。
       官方在场由 DSH 自动遮蔽我方；官方关闭我方自动接管。零检测代码、与加载顺序无关。
       代价：slot id 不再是自有（C3 修订）；官方未来若改用同 priority 会抛错，由 try/catch 兜成"让位"。
   乙「自有 id + 运行时检测」：保持 C3。用 ctx.slots.entries() 探测官方是否注册 + ctx.slots.subscribe()
       订阅变化，在场则 return null。代价：产物须出现官方 slot id 作为只读探测常量（C13 修订为"只允许一次"），
       且自研一套订阅与早退逻辑（早退必须放在所有 hook 之后，否则 hook 顺序会变）。

未验证：两种机制都没有在真实浏览器里跑过；官方关闭后"即时接管"依赖注册表通知触发重渲染，未实测。
